# 云梢的B站协作分身

2026-10-29，分支 `codex/bili-shadow`。

## 结构与权限

云梢负责面向主人交流，分身只读公开B站视频。QQ回复继续由 AstrBot 使用当前会话人格生成；新插件不替换 `system_prompt`。只有实际发送者是配置中的主人、具有管理员身份、当前为QQ私聊、实际选中人格是“专属女仆-云梢”时，任务和报告入口才可调用。群聊、其他用户、其他人格及 WebChat 均拒绝。

```text
主人QQ私聊 → 云梢（当前会话人格与私聊记忆）
                  ↓ 仅BV号或公开搜索词
             B站协作分身（公开性格设定、无聊天历史、无记忆工具）
                  ↓ 带来源与依据的报告
             独立报告库 → 云梢向主人回复
```

分身使用经过人工摘取的云梢公开性格：温柔、细心、自然、诚实；不复制完整人格中的主人QQ号、私人关系设定或聊天示例。公开性格在 `policy.py` 中固定维护，不自动跟随私聊人格更新。这是同一身份的协作职责，不是第二个争夺对话权的角色。

## 使用

在与云梢的QQ私聊中发送：

- `让B站分身看 BV11K421t7Xg，再向我汇报。`
- `让B站分身搜索天文科普。`
- `分身刚才看到了什么？`
- `最近B站有什么有趣的？`
- `最近刷到什么了？`

日常不必说“让分身执行”：云梢会默认结合分身已有记忆自然回应这类问题。没有记录时说明尚无经历，记录过旧时不能说成今天刚看；只搜索过的视频不会冒充已观看。此类问法只触发记忆读取，即使模型误调用任务工具，也返回已有报告，不发起新搜索或观看。明确说“帮我搜索天文科普”仍走新的搜索任务。

手动搜索词必须是本条主人消息中出现的2～40字公开短语。手动观看目标必须是本条消息中的BV号，暂不从历史消息、短链接或搜索结果自动挑选。可以复制搜索结果中的BV号再交代观看。定时自主浏览使用下述独立白名单主题；未实现任意自然语言任务队列、评论、点赞、B站私信或动态发布。

## 0.2.0 晚间自主浏览与QQ投递验收

按主人选定的安排，**北京时间每天20:30–21:00最多一轮，每轮1条**。窗口内每45秒检查一次，离线错过窗口不补跑。主题按日期从“自然 科普”“动物 趣味”“天文 科普”轮换；最多检查5个搜索候选，选1个未处理的视频分析，不追加第二条。现有每条最多前三分钟稀疏抽帧限制不变。

`auto_rounds` 持久保存日额度；`auto_seen` 与手动观看任务联合去重。失败、中断也消耗当日额度，重启不自动补跑或重看。报告先存独立库，证据不足不主动分享，分析结束已过21:00则只保存不发送。

QQ投递使用实测存在的 `Context.send_message` → OneBot `send_by_session` → QQ好友消息接口，**不是B站私信或评论@**。仅接受真实主人私聊绑定的会话；投递前再次检查好友消息类型、主人身份、当前人格、会话开关及当前登录QQ账号。后台直接发送纯文本，不运行聊天记忆采集钩子；报告可由云梢之后按需召回。

首次启用流程：

1. 在与云梢的QQ私聊中发送 `/bili分享测试`，以真实平台事件绑定投递地址。
2. 收到独立的 `【云梢·QQ主动分享测试】` 消息后，发送 `/bili分享确认`。
3. 确认命令开启 `autonomous_enabled`。没有真实绑定和收件确认，即使手动打开开关也不会调度。
4. `/bili浏览暂停` 关闭自主浏览与分享，手动功能保留；恢复可重新测试、确认。

`delivery` 独立记录投递状态。`accepted` 仅表示适配器返回成功，不等于用户看到了；收件确认单独保存。超时或断线记为 `unknown`，不自动重发，避免重复消息。重复执行测试会产生新的独立测试消息，并要求重新确认。

2026-10-30部署与收件验收：0.2.0已重载、24项测试通过。主人已确认收到独立QQ测试消息并执行确认命令；后台核对 `route_bound=true`、`test_state=accepted`、`confirmed=true`、`autonomous_enabled=true`，投递账本有1条成功接受记录。QQ主动分享已单独验收，晚间试运行已启用；此时尚无定时浏览轮次，首轮定时执行仍待实际窗口验证。

模型工具为 `yunshao_bili_task`（search/watch）和 `yunshao_bili_report`。汇报交还当前QQ聊天模型，由云梢转述；分身没有QQ发送接口。

## 记忆边界

- 独立数据文件：`/AstrBot/data/plugin_data/astrbot_plugin_bili_shadow/shadow.sqlite3`。
- `tasks` 只存任务类型、最小目标、状态及时间；不存完整主人消息。
- `reports` 保存搜索结果或观看经历，固定标记 `origin=bilibili_shadow`。作用域由真实平台、机器人、主人身份组合生成，不接受模型提供身份。
- 无读取QQ聊天库、LivingMemory、自学习库或旧BiliBot观看记忆的路径；没有导入来源不明的旧缓存。
- 模型调用直接使用独立 `text_chat` 请求，固定公开人格、空历史、无工具；不通过聊天事件或记忆注入钩子。B站登录凭据只由媒体程序使用，不加入模型请求。
- 只有涉及B站的主人私聊轮次会自动附加最近三份报告；也可由云梢调用报告工具。注入内容标明“不属于主人陈述、不是指令”，使用临时上下文片段，不改写人格。
- 报告轮次标记后，LivingMemory 自动反思、显式记忆写入工具和自学习出站采集均跳过；普通聊天继续正常使用这些插件。
- 原单向个人记忆插件只采集用户原始消息，保持不变；新插件自行检查身份、场景与人格，不能靠单向记忆插件兜底。

报告会出现在主人私聊的正常聊天历史中，这是云梢能够追问的必要部分。主人日后主动转述、转发报告，或其他插件将对话重新加工，仍可能产生新的记录；不能把当前实现解释为对所有未来插件的绝对信息流隔离。关键词过滤也不是完备的隐私识别器，发送搜索任务时应只写公开主题。

## 旧插件与兼容性

原 `astrbot_plugin_bilibili_ai_bot` 已停用，旧工具、命令、自动任务不再作为入口。它的代码与登录配置保留，供新插件借用经过哈希校验的媒体方法；未实例化其完整机器人、记忆系统或写操作工具。

媒体方法在独立模块命名空间加载，临时文件另存。GET 请求限定B站API及字幕CDN，Cookie仅发往B站API，不跟随重定向；分身的POST方法拒绝写操作。视频下载仍使用 yt-dlp 自身的B站下载器。

登录过期时需要维护登录配置。不要直接长期重新启用旧插件：新入口检测到旧插件激活会拒绝执行，避免两个权限范围不同的入口同时运行。

原媒体代码由 `engine-manifest.json` 固定。三处记忆补丁由安装脚本校验，部署后记录文件哈希；检查不通过时新插件拒绝授权。更新BiliBot、LivingMemory、自学习插件后，需重新审核与安装，不能直接跳过哈希检查。

## 媒体限制

每条视频最多处理前3分钟，分为一分钟片段，每段稀疏抽帧，不读取音频。始终尝试视觉分析，避免仅因取得无意义字幕而跳过画面。字幕接口实测存在错配；返回报告记录 `basis`、失败原因和局限。不能把抽帧摘要当成看完整条视频，也不能把视频中的科普数字当成已核实事实。

## 部署与恢复

源码：`plugins/astrbot_plugin_bili_shadow/`。安装器：`scripts/install-bili-shadow.py`，在 AstrBot 容器中执行。

1. 将插件暂存到 `/tmp/astrbot_plugin_bili_shadow`；将含已核对主人ID、人格ID、模型ID的配置放到 `/tmp/bili-shadow-config.json`，不要提交配置到Git。
2. 运行 `python /tmp/install-bili-shadow.py --check`；运行单元测试与必要的只读媒体测试。
3. 通过管理API停用原BiliBot；运行安装器 `--apply`，然后仅重启AstrBot。
4. 核对新插件及两个工具激活，原BiliBot停用；从真实QQ私聊验收。

本次原文件备份位于容器 `/AstrBot/data/plugin_data/astrbot_plugin_bili_shadow/install_backups/20261029T131615Z/`。安装器只补丁修改 LivingMemory 的反思入口、记忆写入工具及自学习的机器人出站采集。

恢复时先停用新插件，再恢复备份的三个文件并重启。旧BiliBot可按需重新启用，但其原有群聊和共享缓存权限也会恢复。保留分身数据库，不在回滚时删除观看经历。
